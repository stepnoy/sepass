#+TITLE: Модель угроз, доступ и восстановление

* Активы и границы доверия
Секреты записей, аппаратный decryption key, Git credentials, список получателей,
история ciphertext, локальный журнал и metadata index имеют разные границы.
Git-сервер и содержимое remote не считаются доверенной инструкцией к выполнению.
Main app, AutoFill extension, iOS identity store и Mac GPG — разные участники.

| Угроза | Мера | Остаточное ограничение |
| Утечка Git clone | Только OpenPGP ciphertext | Имена/размеры/время/UID публичных ключей видны; остаётся offline-анализ |
| Украден заблокированный телефон | SE key + ACL, file protection, автоблокировка | Безопасность ОС/код разблокировки и выбранная ACL важны |
| Захвачен разблокированный процесс | Минимальный RAM-кеш, timeout, отсутствие секретных логов | SE не защищает plaintext уже разрешённой операции |
| Подмена получателей через Git | Локально утверждённая policy, review fingerprint diff | Первый trust anchor требует внешней проверки |
| Фишинговый сайт | Exact hostname, видимый origin, ручное подтверждение mismatch | Целевое приложение получает заполненный секрет |
| Конкурентный writer/сбой питания | OID/policy checks, журнал, атомарная публикация | Нужны fault-injection испытания, не только happy path |
| Старый ciphertext после отзыва ключа | Ротация паролей, понятная история | Отзыв не уничтожает старые доступные копии |
| Злонамеренные PGP/ZIP/Git данные | Bounds, fuzz, traversal checks, integrity verification | Необнаруженные ошибки библиотек остаются возможны |

* Политика ключей
Default: Secure Enclave P-256, privateKeyUsage + biometryCurrentSet,
WhenUnlockedThisDeviceOnly. Пароль приложения сам по себе не заменяет эту ACL.
Изменение зарегистрированной биометрии может инвалидировать ключ; заранее
нужен отдельный резервный OpenPGP-получатель и подтверждённый recovery drill.

Переиспользование unlock context допустимо только в пределах явно определённой
сессии. Background/silent credential calls не выполняют новую биометрию.
Кеш расшифрованных полей не записывается на диск в базовом дизайне. Если
потребуется persistent encrypted index, отдельный ADR определит ключ, ACL,
retention, инвалидирование и риски; не называть его «бесплатной оптимизацией».

Git token не является ключом расшифровки. Хранить отдельно от SE metadata и
общей группы расширения. Миграция донора: прочитать старый UserDefaults credential,
записать в приватный Keychain, проверить чтение, заменить конфиг ссылкой,
удалить старое поле. Ошибка Keychain не должна удалить единственную рабочую
копию credential. Отчёт миграции не содержит token. Ротация старого credential
предлагается после успешного перехода; прошлые backups могли содержать старую копию.

* Сессия, отображение и копирование
Не сохранять plaintext в crash attachments, analytics, debug prints, UserDefaults,
SQLite, Spotlight, notification payload, URL/deep-link parameters или clipboard
без действия пользователя. Диагностика по умолчанию содержит код стадии и
счётчики, без имён записей/remote tokens/запросов поиска.

Clipboard по явному действию: local-only, короткий expiry; таймер не должен
стереть более позднее содержимое, скопированное другим приложением. Экран
app switcher закрывать privacy overlay. Нельзя гарантировать запрет всех
скриншотов и фотографирования экрана. При уходе в background отменять поиск,
очищать session cache; свежие foreground callbacks не оживляют старую сессию.
Swift String/Data могут копироваться: гарантированное обнуление всей RAM не заявляется.

* Ограничения входных данных
Начальные защитные лимиты: ciphertext записи 1 MiB, decrypted text 4 MiB,
число записей для performance теста до 10 000; bounded packet nesting,
decompression ratio/absolute size, ZIP total size и Git pack expansion.
Каждый превышенный лимит — явная ошибка, не молчаливый пропуск данных.
Пороги должны быть централизованными и измеренными на устройствах; snapshot
расширения ограничивается отдельным измеренным бюджетом памяти.

Проверять новые строки/control chars в полях, URL userinfo/scheme/IDNA, traversal,
symlinks, Unicode normalization и case collisions. Секретные JSON исходники
импортёра сохранять только внутри шифротекста, не в отчёте об ошибках.
Не импортировать private key из .public-keys; обнаружение такого блока останавливает
процесс с предупреждением, без вывода содержимого.

* Восстановление и смена устройства
1. Иметь независимую резервную идентичность (например ключ на YubiKey) среди
   получателей и зашифрованную резервную копию Git вне единственного сервера.
2. На новом телефоне создать новый SE key; получить public key и fingerprint.
3. На доверенном устройстве/через доступный старый ключ добавить получателя,
   перешифровать затронутые файлы, проверить независимую расшифровку.
4. Синхронизировать и проверить чтение/поиск/AutoFill новой установки.
5. После проверки исключить старый телефон из новых получателей при необходимости.

SE key не экспортируется как обычный PGP secret key; iCloud backup нельзя
считать способом восстановить его на другом устройстве. Потеря всех секретных
ключей получателей означает потерю содержимого. Приложение объясняет это
при настройке и проверяет наличие recovery-плана, не заставляя хранить
экспортируемый секретный ключ телефона ради удобства.

При компрометации: отозвать Git credential и сервисные сессии, исключить
скомпрометированного получателя, сменить затронутые пароли. Поиск по истории
может требовать старых ключей; UI различает «ключ отсутствует» и «данных нет».
