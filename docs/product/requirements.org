#+TITLE: Требования и пользовательские сценарии

* Целевая аудитория и платформа
Первый продукт — iPhone/iPad, личный Git-репозиторий на Gitea/GitHub/GitLab,
совместная работа с pass/prs на компьютере. Mac с pass остаётся полноценным
участником, но не обязательным редактором для повседневных операций.
Предлагаемый baseline: iOS 17+, Swift/SwiftUI и нативное AutoFill-расширение;
минимальная версия уточняется на этапе проверки SDK и целевых устройств.

Удобство Proton Pass используется как ориентир сценариев: открыть, найти,
заполнить, изменить и синхронизировать. Не копируем обещания облачного сервиса:
вместо его аккаунтов и backend используются Git и OpenPGP-получатели.

* Требования P0
| ID | Требование | Наблюдаемый результат |
| APP-01 | Локальная работа | Существующие записи доступны без сети после разблокировки |
| READ-01 | Чтение pass/prs | Бинарный и armored OpenPGP; понятные ошибки неподдерживаемых форматов |
| SEARCH-01 | Поиск содержимого | Находит login/email/title/URL/note при непрозрачном имени файла |
| SEARCH-02 | Честная полнота | Видны прогресс, недоступные записи и признак неполного результата |
| WRITE-01 | CRUD | Создание, генерация пароля, редактирование, удаление и восстановление |
| WRITE-02 | Все получатели | Запись шифруется каждому получателю действующей .gpg-id |
| WRITE-03 | Без потерь | Неизвестные поля и нетронутые части текста сохраняются |
| ORGANIZE-01 | Папки и имена | Создать папку, перенести/переименовать, обработать коллизии |
| SYNC-01 | Автообновление | Проверка remote при запуске/возврате в приложение |
| SYNC-02 | Автоотправка | Сохранение локально сразу, отправка при доступной сети |
| SYNC-03 | Конкурентность | Конфликт не теряет ни одну версию; нет автоматического force push |
| KEY-01 | Общие public keys | Репозиторий содержит публичные ключи; импорт в клиент по отпечаткам |
| KEY-02 | Подтверждение политики | Добавление получателя не становится доверенным только из-за pull |
| LOCK-01 | Разблокировка | Face ID/Touch ID и явно ограниченная сессия доступа |
| FILL-01 | Системный AutoFill | Safari и приложения; выбор записи, правильные username/password |
| FILL-02 | Секретный login | AutoFill не зависит от логина в имени файла |
| OTP-01 | TOTP | Показ/копирование кода из otpauth URI и сохранение исходного URI |
| IMPORT-01 | Миграция | Proton JSON/ZIP: предварительный отчёт, коллизии, контроль результата |
| RECOVER-01 | Восстановление | Потеря телефона не лишает доступа при наличии резервного получателя |

* После первого выпуска
P1: SSH Git с проверкой host key; несколько репозиториев; ярлыки/теги,
экспорт/импорт дополнительных форматов, отдельные поля карт/идентичностей,
опциональные системные подсказки по расшифрованным URL, улучшенный кеш поиска.
TOTP AutoFill, passkeys, NFC/YubiKey как ключ iPhone, вложения и совместный доступ
команды требуют отдельных спецификаций. Хранение passkey JSON не означает
поддержку входа по passkey. Почтовые алиасы не превращаются в работающий
сервис пересылки от переноса записи. Обещаний этих функций в P0 нет.

* Основные экраны
- Хранилище: папки/записи, поиск, создать запись; индикатор блокировки и синхронизации.
- Поиск: результаты по полям, прогресс расшифровки, фильтр доступности/папки.
- Запись: title, login, скрытый пароль, URL, TOTP, заметки, остальные поля;
  действия редактировать/перенести/удалить/история. Раскрытие пароля — отдельное действие.
- Редактор: генератор, повторяемые URL, заметки; расширенный текстовый режим
  для незнакомого формата. Сохранить означает долговечную локальную запись.
- Синхронизация: последняя успешная проверка/отправка, очередь, ошибки, конфликты.
- Ключи: свой отпечаток/экспорт public key, получатели папки, источник доверия,
  проверка резервного доступа, добавление устройства.
- Настройки: автоблокировка, AutoFill, Git credential, фоновые обновления,
  политика раскрытия метаданных, диагностика без секретов.

* Пользовательские потоки
Подключение: адрес/ветка → HTTPS credential через защищённый ввод → проверка TLS
и прав read/write → clone в staging → проверка структуры и получателей →
подтверждение отпечатков → создание ключа телефона/экспорт public key →
добавление его в получатели и перешифрование доступным прежним ключом.
Если новый телефон ещё не получатель, покажем точную инструкцию для Mac;
не обещаем расшифровать старые файлы просто добавлением public key в репозиторий.

Поиск: пользователь вводит email → разблокировка → появляются совпадения
из расшифрованных полей даже у файла main.gpg. Искать пароль/секретные
дополнительные поля можно отдельным режимом «Всё содержимое»; содержимое
пароля не появляется в сниппетах. По умолчанию не журналируем запросы.

Создание: выбрать папку → ввести данные → показать получателей (без обязательного
диалога на каждую обычную запись) → сохранить → «Сохранено на устройстве,
ожидает синхронизации» → «Синхронизировано». Ошибка сети не отменяет сохранение.

Изменение на Mac: пользователь возвращается на iPhone → доступна локальная
копия → автоматически fetch → безопасное применение → обновление результатов
и AutoFill. Открытый редактор не теряет несохранённый ввод.

* Значение статусов
«Сохранено» — шифротекст и журнал операции долговечно записаны локально.
«Синхронизировано» — remote подтвердил commit, содержащий эту операцию.
«Офлайн» — локальные данные доступны, новизна remote не подтверждена.
«Нужно действие» — конфликт, политика получателей, credential или недоступный ключ.
Не показывать «Всё актуально» после ошибки или отмены fetch.

* Имена и приватность
По умолчанию имя новой записи — main, затем account-<случайный короткий ID>,
без email/login. Пути lowercase ASCII с транслитом; Личное→my, Работа→work.
Домен в пути допустим как явный компромисс; непрозрачные папки тоже поддерживаются.
Title/login внутри шифротекста сохраняют исходные язык и регистр.
Внешние Unicode/смешанного регистра пути читаются без принудительного переименования.
Текущий импортёр ещё использует login в имени: перед реальным импортом нужно
изменить его настройку/политику; одна документация не меняет скрипт.

* Доступность
Dynamic Type, VoiceOver без автоматического чтения скрытых паролей, понятные
ошибки без стеков, отменяемые длительные операции, отсутствие обязательных
жестов без кнопочной альтернативы. Русский и английский UI — цель P0.
