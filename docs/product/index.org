#+TITLE: Pass Client — проект полноценного менеджера секретов
#+DATE: 2026-10-02

* Назначение документации
Проектируем новое приложение на фундаменте pass/OpenPGP/Git. SEPass — донор
проверяемых компонентов, а не готовая архитектура продукта. Название Pass Client
рабочее. Это спецификация и план реализации, не заявление о готовности приложения.

Пользовательские требования: содержательный поиск без логина в имени файла,
создание/редактирование/удаление, организация папок, автоматическая синхронизация,
Safari/iOS AutoFill, аппаратный ключ телефона, доступ резервных YubiKey,
публичные ключи рядом с получателями в репозитории, перенос данных из Proton.

* Статус и приоритеты
Документация фиксирует целевой полноценный первый выпуск. Промежуточные этапы
нужны для проверки рисков; просмотрщик без записи/поиска/автосинхронизации
не считается выполненным продуктом.

P0: обязательный первый выпуск. P1: следующий этап после рабочего ядра.
SPIKE: эксперимент, результат которого нужен ДО обещания соответствующей функции.
Статусы требований ниже — planned, если явно не указан другой статус.

Порядок: аппаратные и библиотечные эксперименты → формат и транзакции → поиск →
редактор → двусторонняя синхронизация → AutoFill → миграция и аппаратная приёмка.
Главные риски: биометрия при массовой расшифровке; полноценная запись OpenPGP
на разные алгоритмы получателей; Git merge/push; совместное использование
Secure Enclave ключа приложением и расширением.

* Границы текущей работы
Созданы документы. Новый продукт не реализован; реальное хранилище и экспорт
Proton не изменяются. Предыдущая ветка AutoFill остаётся прототипом и донором.
PR не отправляется. Публичная документация не содержит настоящих секретов,
путей аккаунтов, токенов или содержимого экспорта пользователя.
